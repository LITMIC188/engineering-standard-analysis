# Local adapters and third-party boundaries

## translation-quality-codex (TQC)

Primary source inspected: [WenhaoLiu0218/translation-quality-codex](https://github.com/WenhaoLiu0218/translation-quality-codex), installable folder `skills/translation-quality-codex`. The public `main` SKILL.md specifies a long-form package with `source_blocks.json`, `translation_aligned.md` retaining `S0001` anchors, clean `translation.md`, glossary, review feedback, notes, and a package validator. The public [prepare script](https://raw.githubusercontent.com/WenhaoLiu0218/translation-quality-codex/main/skills/translation-quality-codex/scripts/prepare_translation_job.py) accepts a Markdown/plain-text path, `--out-dir`, `--source-lang`, `--target-lang`, and `--max-block-chars`; it rejects PDF/DOCX as requiring extraction first. Its splitter keeps detected Markdown tables intact but splits long ordinary text. The public [readable-output script](https://raw.githubusercontent.com/WenhaoLiu0218/translation-quality-codex/main/skills/translation-quality-codex/scripts/build_readable_output.py) parses audit anchors with `^##\s+(S\d{4,})\s*$`; the public [package validator](https://raw.githubusercontent.com/WenhaoLiu0218/translation-quality-codex/main/skills/translation-quality-codex/scripts/validate_translation_job.py) checks required package files and anchor presence (not translation semantics). This adapter follows the actual `## S0001` heading format. It does not call any TQC script: it writes the compatible `id/type/text` source block core, aligned scaffold and a saved ID map. Whole clauses and tables remain indivisible; oversize blocks are flagged for human boundary selection.

At inspection, branch was `main`; a stable commit SHA could not be established from the accessible primary pages. The repository root showed no `LICENSE` file (raw LICENSE returned 404), so licensing is unverified. No TQC dependency was installed or executed. Use the skill's own review/translation workflow only when the user or session makes it available. Import only its edited `translation_aligned.md`; the importer demands an exact one-to-one set of IDs and rejects missing, duplicate, unexpected, or pending translations. Translation does not itself establish technical correctness. `human_reviewed` remains false.

## Adapter contract

`prepare_translation(clauses, output_dir, max_chars=1800)` accepts the framework clauses object (`schema_version: "2.0"`, `blocks[]`) and writes a TQC-compatible `source_blocks.json`, `translation_aligned.md`, and `adapter_manifest.json`. It refuses an existing output directory. Each emitted block carries original framework IDs, clause ID, source file/hash/page locator and protected tokens as metadata; each original text remains whole. `max_chars` only flags blocks exceeding the limit. The manifest's `id_map` and block hashes must travel with the aligned file so clause reordering cannot silently change ID mappings.

`import_translations(clauses, aligned_file, id_map=None)` imports the audit Markdown and returns framework `{"schema_version":"2.0","segments":[...]}`. It loads the prepared `adapter_manifest.json` beside the aligned file by default, or accepts its `id_map` explicitly; without a map it requires a matching `<!-- block_id: ... -->` comment below each anchor. It rejects missing, duplicate, unknown, or pending IDs. It preserves the source dictionary and copies its original text into both `original_text` and `source_quote`, along with page, language, clause and protected tokens. Target language defaults to `zh-CN`; change it in the framework contract before using a different route. Every imported segment starts `human_reviewed: false`. Run the framework translation validator afterward. Its JSON Schema must allow `pdf_page: null` for non-PDF sources.

CLI examples (all operations are local):

```powershell
python scripts/adapters.py --help
python scripts/adapters.py prepare clauses.json run/translation --max-chars 1800
python scripts/adapters.py import clauses.json run/translation/translation_aligned.md run/translation_segments.json
python scripts/adapters.py doctor C:/Users/me/.codex/skills C:/Users/me/.agents/skills
```

Translation review for standards must compare every aligned clause to its original. Preserve `shall`/`should`/`may` force, Japanese obligation and prohibition forms (including `しなければならない`, `してはならない`, and qualifications), negation, exceptions, defined terms and table references. Check terminology against the source's definitions and any authorized bilingual terminology source. Numeric/token checks are useful but insufficient; no adapter can certify translation meaning. Mark unclear source text and unresolved language questions for a qualified human reviewer.

`doctor(roots)` only checks the explicitly passed root directories for known `<root>/<skill-name>/SKILL.md` locations and checks `python`, `python3`, `docling`, and `mineru` on PATH. It does not recurse, invoke a tool, install dependencies, or validate compatibility. `local_available` means only that a folder was found; `contract_only` means this framework documents a route but has no discoverable skill folder; `missing` means no local folder or route implementation was found.

## Tool routing status

The eight non-translation tools in `references/skill-routing.md` are routing candidates, not integrated APIs. `doctor` reports them as `contract_only` when the named skill folder is absent and `local_available` only when its `SKILL.md` is found; that status does not imply an execution adapter. This framework has a local parser and its own audit validators; no direct adapter is claimed for Docling, MinerU, doc-query, doc-extract, doc-compare, Traceability Matrix, iso-standards-readiness, or MinerU Document Explorer. Select those tools only after inspecting the actual local skill interface, dependencies, license, network behavior, and output contract. Prefer local execution; do not send standards to hosted services without explicit authorization. For complex layout, use a locally available parser and visually verify tables/page anchors. For editable OOXML translations or book-scale documents, route to the optional format-preserving / book translation skills only after confirming they are locally present and suitable. `academic-paper-translator` is likewise optional and is not a standards facts source.

No route, local installation, or third-party tool proves that a translated requirement or experiment conforms to a standard. Report inaccessible, uncertain, OCR-derived, and unreviewed material explicitly.
