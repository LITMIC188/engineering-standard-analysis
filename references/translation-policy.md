# 外文技术标准翻译策略（ISO/JIS/IEC/DIN/CGA...）

## 输入前检查
1. 记录原文标准版本、语言（精确识别，如 `en`, `ja`, `de`, `fr`）、译文目标 `zh-CN`、合法持有/保密边界及有无官方译本。
2. 用户没有明确授权不得将标准原文传入外部付费 API、远端 OCR 服务或公开仓库；优先使用已许可的本地文件和 Codex 当前环境。
3. 译文只作为阅读辅助，最终验收标准与条款解释须返回原始外文条款确认。官方译本如有须记录版次和优先关系，不得假设同等权威。

## 强制保留
- 标准号、年份、条款号、表/图/附录、脚注、交叉引用、公式变量及公差表达；保持 `pdf_page` 为**原文件物理页码**（从 1 起），另外记录印刷页码。
- 测试对象、限制条件、样品批次要求、方法/设备、操作顺序、判定条件、规范性引用，不能省略或“概括翻译”。
- 数字、±、≤、≥、小于/不大于、以上/以下、范围端点、科学计数、温度、压力单位（kPa/MPa/bar）、体积流量单位、摄氏度、角度和气体组分。
- 警惕全半角混用、OCR 的 1/l/I/丨、0/O、负号、点/逗号、希腊字母 μ/µ、上/下标以及指数。自动检查仅初筛，不能取代人工页图核查。

## 模态词与文本性质
- 英文 `shall` / `should` / `may` / `can` 必须结合标准的语义规定与句法分析；不能简单映射为“必须/建议/可以”。
- 日文 `～しなければならない`、`～すること`、`～するのが望ましい`、`～してもよい` 等应按上下文及该标准的用语规则判定；这些是**审查线索**而非机械词典。
- 特别保留 `unless`, `except`, `only if`, `at least`, `not less than`, `not exceed` 及日文限定、否定与例外语句。
- 标记正文、注、示例、参考附录、规范性附录，不得把解释性内容自动升级为约束。

## 分块/术语/输出
- 原文块按**条款或表格整体**切分，给唯一 `block_id`（例如 `B0001`）；整张表不可切半；原文哈希/范围可复核。
- 生成术语表 `glossary.json`：`source_term`, `language`, `zh_term`, `context`, `source`, `status`；日语/英文同义词需要保留不同的来源。
- 双语对齐表 `translations/segments.json` 每条含 `block_id`、`clause_id`、`pdf_page`、`original_text`、`translated_text`、`source_lang`, `target_lang`, `human_reviewed`, `protected_tokens`。
- 翻译来源校核先做自动块 ID / 数字 / 指定保护令牌检查，再由工程人员对译法、术语、强制性、负号与例外作语义复审。疑点留在 `review_queue.csv`。
- `translation-quality-codex` 的输出 ID (`S0001` 等) 需在适配层映射为标准条款块 ID；清洁阅读版可不显示 ID，但审计版必须保留。

V2.1 已实现其 `## S0001` 审计 Markdown 文件适配和源块哈希映射，见 [adapters.md](adapters.md)。`validate_translation.py --strict` 为初筛，会检查 SI 单位大小写、数字、比较符、部分代数/化学公式与指定保护记号；复杂排版公式、上下标 OCR 和文字表达的比较关系仍需原页审核。记录完备也不能使脚本证明译文语义正确。译文须保留 `source_quote`，非 PDF 来源使用 null 页码和真实 locator。

## 来源优先级
1. 具备版本识别和页码锚点的标准原文；2. 同来源的表/图原页；3. 经核实的正式译本/术语；4. 机器译文；5. 工程解读和第三方文章。
最终判断要求 1 或 2，译文或二手材料不足以单独支持肯定判断。
