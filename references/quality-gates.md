# 质量门禁

| Gate | 要点 | 阻断条件 |
|---|---|---|
| QG0 文件来源 | 版本、SHA256、权限、标准完整性 | 原文件缺失/无法识别来源 |
| QG1 文档提取 | PDF页码、图表、条款号、页图复核 | 关键内容 OCR 不可信 |
| QG2 章节覆盖 | 正文、规范性附录、表、图、例外、引用 | 规范性章节漏检 |
| QG3 翻译对齐 | 块ID、数字、符号、模态、术语、条件 | 强制性/否定、数值未审或冲突 |
| QG4 工程要求 | 原文/译文/推导分离；条件、单位、来源 | 单位、限值或适用性未知却给确定结论 |
| QG5 实验方案 | 所有适用要求有映射、无映射有记录 | 未审查就得出总方案符合结论 |
| QG6 实验原子字段 | 方法、条件、仪器、样品、测量、准则、记录 | 关键字段缺失却标 aligned |
| QG7 人工审核 | 修订记录、审核人、原始证据 | 无人工审核却写 approved |
| QG8 学习资料 | 教材附加知识与标准原文分离 | tutor 输出反哺修改规范内容 |
| QG-source 原文冻结 | 实际源 SHA、块/跨度、全文哈希、目录清单和真实 source_review | 空清单、缺页/规范性附录、未审关键 OCR、任意文章替代冻结正文 |
| QG-publish 发布 | 门禁→Markdown→Bases→格式/链接/附件→事务→CLI回读 | 越界、哈希变动、缺附件、冲突、未验证运行实例 |

## 严重度
- `critical`：强制安全相关试验条件明显不符，或关键数值无法确认但将导致风险判断。
- `major`：方法/限值/判定准则缺失或不匹配。
- `minor`：补充记录、编号、格式等不影响方法本质的问题。
- `unknown`：无法判断，交给审核人确认。

## 状态纪律
- `draft`：AI草案；`source_checked`：核对原文出处；`engineering_reviewed`：专业人员复核工程解释；`approved`：记录已被指定审核人正式审签（不代表产品合格）；`blocked`：需补充重要材料。
- `source_verified=true` 必须有回到原 PDF 实体页/表格核对的记录，不可因为 LLM 输出完整就置 true。
- `experiment_audit` 中的 `aligned` 不等于实际试验符合，也不等于产品获证；`not_assessable` 应计入未闭环项而非自动算通过。
- 每个试验先独立核对，真实协议/阶段/样品组与组合证据才能支撑联合判定，不能从无关项目拼出方法和工况。
- 全局章节、规范性附录、表、图、引用文件覆盖与局部字段对齐分开记录；所有局部行 aligned 仍不能越过未闭环的全局门禁。
- 严重度保留审签风险因子及 `risk_rationale`；资料不足为 unknown，不按结论状态固定赋 major。资料性内容不作强制试验缺项，性质与义务冲突必须复核。
- `.base` 是要求笔记的属性索引，不是标准事实数据库。CLI 缺失只证明静态文件检查，不证明应用回读或 UI 展示。发布和恢复日志记录路径、hash、退出码与状态，不记录全文。
